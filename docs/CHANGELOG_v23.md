## v22.1 구매전략 재고운영 기능 보강 (2026.07.21)
- **입고예정금액 카드 연결**: `raw_발주.csv`에서 `입하여부`가 비어 있는 미입하 발주를 읽고, `재고귀속파츠번호` 우선으로 `parts_master.csv`의 `표준원가`를 매칭해 `발주지시수량 × 표준원가`로 입고예정금액을 계산합니다. 카드 클릭 시 SKU별 상세 모달을 표시합니다.
- **신제품 재고비중 카드 신규**: `dashboard_group_summary.csv`의 `group_type=new_product`와 `dashboard_sku_snapshot.csv`의 `is_new_product`, `is_first_order` 플래그를 사용해 신제품 재고금액, 전체 대비 비중, 초도발주/재발주완료 구성, 초도 예외 SKU를 표시합니다.
- **시즌별 재고회전율 카드 신규**: `dashboard_group_summary.csv`의 `group_type=season`과 `dashboard_sku_snapshot.csv`의 `season_type`을 사용해 여름/겨울/봄가을별 재고금액, SKU 수, 1M/3M/YTD 회전율을 표시합니다. 기준일 월로 현재 시즌을 강조합니다.
- **수동 업로드 자동인식 보강**: 자동 로드에는 이미 포함돼 있던 `dashboard_sku_detail.csv`, `dashboard_sku_monthly.csv`, `raw_발주.csv`, `parts_master.csv`를 드래그 업로드해도 파일 유형을 인식하도록 `FILE_SIGNATURES`를 추가했습니다.
- **원본 CSV 헤더값 변경 여부**: 기존 헤더명 변경은 없습니다. 단, 신규 기능은 아래 헤더를 사용하므로 원천 시트에서 해당 헤더가 바뀌면 함께 공지와 코드 수정이 필요합니다: `raw_발주.csv`의 `파츠번호`, `재고귀속파츠번호`, `발주지시수량`, `입하여부`, `입하예정일`; `parts_master.csv`의 `파츠번호`, `파츠명`, `표준원가`, `굿즈카테고리`, `서브카테고리`; `dashboard_sku_snapshot.csv`의 `is_new_product`, `is_first_order`, `season_type`; `dashboard_group_summary.csv`의 `group_type`, `group_name`, `inv_amount`, `sku_count`, `turnover_1m`, `turnover_3m`, `turnover_ytd`.

### 빅딜(대량 발주) 기준 통일 — 제품별 표준분포 80% 범위 초과 (2026.08.04, 사용자 요청)
같은 발주 건이 화면마다 빅딜/정상으로 엇갈리던 문제를 해결했습니다. 기준을 **제품별 발주수량 분포의 표준분포 80% 범위 상단(μ+1.2816σ) 초과**로 통일하고, 두 화면이 공통 함수 `bigDealStat()`/`bigDealMinQty()` 하나만 쓰도록 바꿨습니다.

- **기존 기준 (화면별 상이)**: ① 발주 현황 → 제품 상세 드릴다운 = **건당 평균 발주수량 × 1.1**(v22.17) ② 제품별 판매량 추이 = **IQR 울타리 Q3+1.5×IQR**(v23.7). 같은 제품·같은 발주 건인데 한쪽에선 빅딜, 다른 쪽에선 정상으로 표시됐습니다.
- **변경 기준**: 그 제품의 전체 발주수량 분포를 정규분포로 보고 **중앙 80% 구간의 상단(μ+1.2816σ)을 넘는 발주만 빅딜**(상위 10% 경계). 제품마다 기준 수량이 따로 계산됩니다 — 예: UV(스펙트럼 컬러펜) 2,320개 이상, 브랜디드피규어 484개 이상, 데일리짐색 705개 이상(제품별 판매량 추이 기준).
- **판정 보류 조건**: 표본 5건 미만(표준편차 불안정) 또는 전 건 동일 수량(σ=0)이면 빅딜 없음으로 두고 화면에 사유를 표기합니다.
- **영향(실측, `CSV/order.csv` 3,139건·284개 제품)**: 빅딜 판정 **310건(9.9%)·수량 311,906개(39.7%)**. 직전 IQR 기준 254건(8.1%)보다 넓고, 발주 현황의 평균×1.1 기준 760건(24.2%)보다 크게 좁아집니다. 채택 전 P80(555건)·μ+0.842σ(408건) 안도 함께 검토했습니다.
- **화면 표기 보강**: ① 제품 상세의 "빅딜 기준 수량"에 산출 근거(평균·표준편차·표본 수)를 병기 ② 제품별 발주 요약의 빅딜 제외 배지에 그 제품의 기준 수량을 툴팁으로 표기 ③ 요약 카드 설명이 실제 로직과 달랐던 문구("한 건이 그 제품 전체의 80% 이상") 수정 — v23.7에서 IQR로 바뀔 때 갱신되지 않은 옛 문구였습니다.
- **원본 CSV 헤더값 변경 여부**: 없음 — `발주지시수량` 등 기존 필드만 사용합니다.

### 매출 실측을 연간분석 표 기준에 정렬 — VAT 별도 + 출고 마감 컷오프 (2026.08.04, 사용자 요청)

#### 캘린더 특이사항 GitHub 커밋 (2026.08.04, 사용자 요청)
캘린더 특이사항이 지금까지 **localStorage에만 저장돼 등록한 브라우저에서만 보였습니다.** 진행현황 비고(`progress_notes.json`)와 같은 방식으로 `data/cal_notes.json`에 커밋해 팀 전체가 공유하도록 바꿨습니다.

- **추가·삭제 시 자동 커밋**: `calAddNote()`·`calDelNote()`가 GitHub 토큰이 등록돼 있으면 즉시 커밋합니다. 토큰이 없으면 이 브라우저에만 저장하고 안내 문구를 띄웁니다.
- **🔄 GitHub에 커밋 버튼 신규**: 나중에 토큰을 등록했거나 자동 커밋이 실패한 경우 수동으로 올릴 수 있습니다. 입력폼 아래 상태줄(`cal-save-status`)에 커밋 중/완료/실패가 표시됩니다.
- **덮어쓰기 방지**: 저장 직전 배포본을 다시 받아 **이 브라우저가 직접 건드린 항목만** 얹습니다(`CAL_DIRTY_ADD`는 id로 덮어쓰고 `CAL_DIRTY_DEL`은 id로 제거). 그 사이 다른 사람이 올린 특이사항을 덮어쓰지 않습니다 — 검증: 배포본에 타인 항목 2건이 있는 상태에서 내 항목 1건 추가 + 타인 항목 1건 삭제 시, 남은 타인 항목은 보존되고 내 변경만 반영됨을 확인했습니다.
- **기본 항목(`seed-*`)은 파일에 넣지 않습니다** — 코드의 `CAL_NOTES_SEED`가 정본이라, 파일에 박아두면 정의를 고쳐도 낡은 값이 계속 따라옵니다. 로드 시에도 seed는 배포본 값으로 덮지 않습니다.
- **`data/cal_notes.json` 신규**(빈 배열로 초기화) · 앱 시작 시 `loadCalNotesDeployed()`로 배포본을 받아 로컬과 병합합니다.
- ⚠ 실제 커밋 경로는 개인 액세스 토큰이 있어야 동작하므로 **토큰 없는 상태의 분기(안내 문구·로컬 저장)와 병합 로직만 검증**했습니다. 토큰 등록 후 첫 커밋은 사용자 확인이 필요합니다.

#### 커밋 실패 원인 표시 개선 (2026.08.04, 사용자 제보 — 캘린더 커밋이 안 됨)
