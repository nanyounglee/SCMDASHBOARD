# 구매전략파트 · S&OP 재고운영 대시보드

_SCM 통합대시보드 중 구매전략파트 담당 4개 탭_

---

## 1. 개요

구매전략파트의 재고운영 데이터를 **[원천 데이터 → 자동 집계 → 대시보드]** 까지 자동으로 흘려보내고 그 위에 4개 탭을 얹은 도구입니다. 원래 재고 상태·품절·발주 타이밍이 여러 시트에 흩어져 있던 걸, **재고회전율·품절율 두 지표를 축으로 한 화면에 모아** 같은 기준으로 보게 만들었습니다. 큰 흐름은 **현황 파악(재고·품절) → 의사결정(매입·졸업)** 두 단계로 이어집니다.

**4개 탭** — 현황 파악(①②) → 의사결정(③④)

| 구분 | 탭 | 한 줄 |
| --- | --- | --- |
| 현황 | ① 재고운영 현황 | 지금 재고가 건강한지 (평가액·회전율·운영밴드) |
| 현황 | ② 품절 상세 | 무엇이, 왜 품절인지 |
| 의사결정 | ③ 졸업 검토 | 오래 안 팔린 재고를 정리 대상으로 추림 |
| 의사결정 | ④ 매입검토(EOQ) | 언제 얼마나 발주해야 하는지 |

## 2. 데이터 플로우

원천 데이터를 시트에서 **2단계로 미리 가공**한 뒤, 그 결과를 **CSV 8개로 GitHub에 올리고**, 대시보드는 접속할 때 그 CSV를 불러와 화면에 표시합니다.

```
① 원천 데이터 · Airtable 3개 베이스
     SERPA(재고·판매량·발주)  ·  MRP(판매상태 이력)  ·  신시어리DB(SKU 정보)
        │   Google Sheet로 원본 반입
        ▼
② 1차 가공 (raw → fact) · Apps Script
     inventory_weekly  ·  sales_monthly  ·  재고단가_자동
        │
        ▼
③ 2차 가공 (기간·그룹 단위 집계) · Apps Script
     dashboard 시트 5종
        │
        ▼
④ GitHub 업로드 (매주 목요일 18:00 자동 · 급하면 수동)
     시트 → CSV 8개로 변환·저장
        │
        ▼
⑤ 대시보드 (웹페이지)
     접속 시 CSV 자동 로드 → 화면에 표시
```

### GitHub로 내려가는 CSV 8개 (= 대시보드가 읽는 파일)

**가공 완료본 (2차 가공) · 5개** — 대부분의 화면이 이걸 그대로 표시

| 파일 | 내용 |
| --- | --- |
| dashboard_period_summary | 기간별 KPI |
| dashboard_group_summary | 그룹별(카테고리·조달유형 등) 집계 |
| dashboard_sku_snapshot | SKU 단위 스냅샷 |
| dashboard_sku_detail | SKU 고정정보(굿즈연결·출시일 등) |
| dashboard_sku_monthly | SKU × 월별 판매·품절이력 |

**원본 그대로 · 3개** — "원본 이력"이 필요한 기능이 브라우저에서 직접 계산

| 파일 | 내용 · 쓰임 |
| --- | --- |
| raw_발주 | 발주 내역 원본 — EOQ 리드타임 실측 |
| parts_master | SKU 마스터 정보 |
| sales_status_history | 파츠별 판매상태 변경 이력 — 품절 상세 재구성 |

### 핵심 3가지

- **역할 분리** — 무거운 계산은 시트(Apps Script)에서 미리 해두고, 대시보드는 그 결과를 표시.
- **가공본 5 + 원본 3** — 대부분 화면은 가공본 5개면 충분하지만, 원본 이력이 필요한 기능은 원본 3개를 받아 브라우저에서 직접 계산.
- **갱신 주기** — 매주 목요일 18시 자동 갱신, 급하면 즉시 수동 실행.
  - 수동 실행: GitHub Actions에서 `weekly-google-sheets-csv` 워크플로를 실행하면 됨

## 3. 핵심 지표 정의

### 재고회전율

```
회전율 = 최근 3개월 판매금액 ÷ 최근 3개월 평균재고금액
```

- 판매·재고 둘 다 **"단가 × 수량 = 금액"** 으로 환산 → 수량이 아니라 **금액 기준** 회전 속도.
  - SKU마다 단가가 달라 수량으로 집계하면 왜곡될 수 있음. 회전율은 "묶인 자금이 얼마나 빨리 도는지"를 보는 거라 금액 기준으로 봄.
- 1개월 / 3개월 / 연초누적(YTD) 세 버전을 제공하되, **대표는 3개월**.
  - 선매입재고를 3개월 안에 소진하는 걸 목표로 매입하기 때문에, 수치로는 "3개월 회전율 1"이 목표치. (1개월은 B2B 특성상 수요가 들쭉날쭉해 대표성이 떨어지고, 연초누적(YTD)은 오래된 실적이 섞여 지금 상태를 흐려서 3개월이 균형점 — 분기 S&OP 주기와도 맞물림)
- SKU 단위로 각각 계산한 뒤, KPI에서는 관리대상(Product Parts) 전체를 합산해 대표 회전율 하나로 표시.
- 시즌 제품은 카테고리와 별개로 **"여름/겨울/봄가을"** 로도 따로 봄 (성수기 지난 재고가 묵혀 있는지 확인용).

### 품절율

품절율은 **굿즈(완제품) 단위**로 집계함. 부품 하나가 품절돼도 대체 부품이 있으면 굿즈는 계속 팔릴 수 있어서, "고객이 실제로 못 사는 제품이 몇 개냐"를 보는 게 핵심. (파츠(부품) 단위는 품절'율'(비율)이 아니라 **품절 SKU 수**로 집계하고, 비율로 보는 품절율은 굿즈 단위로만 냄.)

```
굿즈 품절율 = 그 시점 품절로 영향받은 굿즈 수 ÷ 그 시점 운영중이던 굿즈 수
```

- **분자 (영향받은 굿즈 수)** — `sales_status_history`에서 그 시점에 아직 안 끝난(열려있는) 품절 구간 중, 담당자가 "굿즈품절여부"를 직접 체크한 건만 대상. 그 파츠에 연결된 굿즈("적용 굿즈명" — 한 파츠가 여러 굿즈에 쓰이면 여러 개)를 모아 **중복 제거한 굿즈 개수**.
- **분모 (운영중이던 굿즈 수)** — `goods_master`의 출시일~졸업일로 판정해 **그 시점에 이미 출시했고 아직 졸업 안 한 굿즈만** 카운트. 시점마다 달라짐(예: 오늘 223개 · 2023년 156개).
- **목표치** — 1~3분기 3% 이하(재고보유율 97%↑) / 4분기 5% 이하(95%↑). 이 기준은 EOQ 탭 안전재고 계산(서비스레벨)에도 **그대로 재사용**.

## 4. 탭별 기능

### ① 재고운영 현황 — 지금 재고가 건강한가

- 재고자산 평가액, 재고회전율(1개월/3개월/연초누적), 운영밴드(정상/과다/부족) 상태
- 카테고리별·조달유형별·생산구분별 재고 비중과 회전율
- 재고금액 추이, 회전율/선매입재고품절율 추이 차트
- 선매입재고 품절현황(판매상태별 분포, 장기품절 30일+/60일+)
- 신제품(출시 1년 이내) 재고비중 — 초도발주 vs 재발주완료

> ※ 초도발주 판별은 "리오더 지시일"이 아니라 **"실제입하일"** 기준. (지시만 해두고 아직 입하 전인데 통계에서 너무 일찍 빠지는 왜곡을 없앰 — 실측 평균 11일, 상위 10%는 34일 이상 차이)

### ② 품절 상세 — 무엇이, 왜 품절인가

- 굿즈품절율(고객이 실제로 못 사는 완제품 비율) 추이 + 분기별 목표선(1~3분기 3%↓ · 4분기 5%↓)
- 비의도적품절 추이(SKU 수 기준)
- 품절 사유 자동분류 (비의도적 / 의도적 구분)
  - **의도적품절**(의사결정 완료된 사항): 시즌종료 · 리뉴얼예정 · 졸업예정 · 재고효율화 · 리스크대비
  - **비의도적품절**: 공급부족 · 수요초과 · 납기지연 · 리스크발생 · 기타
- 협력사재고·선매입재고 품절 상세
- 파츠별 품절일수 내림차순 상세 테이블
- 주별/월별/분기별 + 특정 기간 조회

> ※ 원천을 `sales_status_history`(파츠별 판매상태 변경 이력 전체)로 바꿈 → **과거 어느 시점이든 품절 상태를 재구성** 가능. 예전엔 우리 장부에 있는 SKU만 봐서 **협력사재고 품절이 통째로 누락**됐는데, 이제 그것까지 다 잡힘.

### ③ 졸업 검토 — 오래 안 팔린 재고 정리

- 3개월 회전율 0.1 미만 + 관리대상 Product Parts 조건의 장기미회전 후보 자동 추출
- 권장조치(운영종료 검토 / 졸업 검토 / 모니터링) 자동 분류
- 후보 재고금액 합계

### ④ 매입검토(EOQ) — 언제 얼마나 발주할까

- SKU별 EOQ(경제적 발주량)·ROP(재발주점)·안전재고 자동 계산
- 서비스레벨(재고 보유 목표, 1~3분기 97% / 4분기 95%) 기준 발주 타이밍 알람
- 조달유형(국내생산/국내소싱/직소싱/중개소싱)별 필터

> ※ 별도 "매입 검토" 탭은 두지 않고 EOQ 탭이 그 역할을 대신함 (시즌재고계획은 별도 시트로 운영, 이 대시보드 범위 밖).

### ⑤ 주간 재고 리포트 생성 — 한 주 현황을 문서로 자동 정리

"리포트 생성" 페이지의 **📦 구매전략파트 주간 재고 리포트 생성** 버튼 → 선택한 주차의 `dashboard_period_summary` 스냅샷을 기준으로 **markdown(.md) 리포트를 자동 생성·다운로드**. (탭이 아니라 리포트 생성 페이지의 기능)

리포트는 5개 섹션으로 구성:

1. **재고 수준·건전성** — 재고자산 평가액, 운영밴드(정상/과다/부족), 신제품 재고금액, 입고예정금액, 생산구분 비중
2. **재고 구조** — 카테고리별 재고, 시즌재고 현황
3. **품절 관리** — 품절 현황 요약, 비의도적 품절 목록
4. **장기미회전재고**
5. **주요 이슈·우선순위** — 주간 변동(전주 대비), 우선순위 소진 이슈, 주요 관리 대상 SKU

> ※ 핵심은 5번 섹션의 **규칙 기반 자동 이슈 판정** — SKU마다 아래 조건을 체크해 🔴긴급 / 🟠높음 / 🟡모니터링 우선순위를 자동으로 매겨줌(사람이 하나하나 안 봐도 됨):
> - 단일 SKU 재고 비중이 전체의 10% 이상 → "재고 과다"
> - 연속 판매 0 — 3주 이상 → "소진 필요"(긴급), 2주 → "높음"
> - 신규 출시(1년 이내) 후 4주 이상 판매 0 → "모니터링"
> - 최근 3개월 판매량이 전주 대비 50% 이상 급감 → "모니터링"

## 5. 한계 및 계획

### 지금의 한계

- **대부분 후행(모니터링) 지표** — 이미 일어난 재고·품절 상황을 모아서 보여주는 역할이 큼. 가령 3개월 뒤 재고 예측이나 품절 예방처럼 앞을 내다보는 부분은 대시보드가 자동으로 보여주기보다 **사람의 판단이 개입돼야 하는 영역**.
- **협력사재고는 "품절 여부"만 알 뿐 "실제 잔여 수량"은 모름** — 우리 장부에 없는 재고라 **데이터로 관리할 수가 없음**. 그래서 협력사재고 쪽은 품절이 임박했는지 미리 볼 수 없어 **품절 대비에 특히 취약**.
- **아직 수기 가공이 많음** — 구글 시트 가공 단계에서 재고귀속 파츠번호, 품절 사유, 굿즈품절여부 체크 등을 사람이 직접 입력·가공해야 함. 그중 품절 사유는 텍스트 기반 자동분류라 표현이 애매하면 "미분류"로 빠지고, 실측 태깅으로 보완하지만 그 필드도 최근 데이터부터만 채워짐.
- **매입검토(EOQ)·졸업검토 모두 "계산기/추천"까지만** — 실제로 발주했는지·졸업 처리했는지 추적하는 상태값이 없어서, 지난주에 추천된 게 이번 주에 또 추천되는지 확인 불가.

### 다음 계획 (구상 중)

1. **부서별 실행 리포트** — 재고회전율을 높이려면 결국 ⓐ판매를 늘리거나 ⓑ안 팔리는 재고를 과감히 졸업시켜야 함. 이를 실제로 실행하는 **CX·마케팅·MD가 각자 볼 수 있는 액션 리포트**를 제공해, 대시보드의 "현황"을 각 부서의 "실행"으로 연결. (예: 마케팅 — 판매 촉진이 필요한 저회전 재고 / MD — 졸업·리뉴얼 검토 후보 / CX — 품절·대체품 안내 대상)
2. **협력사재고를 "품절 여부" → "실제 재고 수준"까지 확장** — 현재 가장 큰 사각지대. 협력사재고는 우리 장부에 없어 품절 여부만 알 뿐 남은 수량을 몰라, 품절이 임박했는지 미리 볼 수 없음. 협력사에서 재고 수량 데이터를 주기적으로 확보(시스템 연동 또는 정기 제출)하면 선매입재고처럼 **재고 수준·소진 속도로 관리**할 수 있고, 나아가 **품절 임박 알림·안전재고(EOQ)까지 협력사재고에 적용** → 선매입/협력사 구분 없이 같은 기준으로 품절에 대비.
